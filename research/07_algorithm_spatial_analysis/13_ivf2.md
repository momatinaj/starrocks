# IVF² (IVF-squared): Fusing Classic and Spatial Inverted Indices

## 1. Algorithm Summary

**IVF²** fuses **classic inverted-file indices** (for categorical or boolean metadata) with **spatial inverted indices** layered on top of an **IVF-style vector index**, so that conjunctive metadata filters shrink the candidate set *before* expensive distance work. Landrum et al., *“IVF² Index: Fusing Classic and Spatial Inverted Indices for Fast Filtered ANNS”* (NeurIPS BigANN Filter Track / reported at ICML VecDB workshop lineage; see `research/01_literature_survey/hybrid_approaches.md` and `research/01_literature_survey/papers/bibliography.bib` entry `ivf2_2025`). The core idea is **dual-index fusion at query time**: bitmap- or posting-list–friendly metadata inversion intersects with vector IVF posting lists.

## 2. Mechanism Deep-Dive

**Build (conceptual):**

1. **Vector IVF layer**: Cluster embeddings (e.g., k-means) into `nlist` centroids; each vector is assigned to one (or few) clusters; inverted lists hold vector IDs per centroid.
2. **Classic inverted indices**: For each filterable attribute value (e.g., label, tag), maintain postings of row/vector IDs (often compressed bitvectors for high selectivity).
3. **Fusion metadata**: Maintain mappings so that the intersection of (a) vectors in probed IVF lists and (b) vectors matching metadata predicates is computable without full scans.

**Query:**

1. Evaluate **metadata predicates** using classic inverted intersections (AND → intersection of postings/bitmaps).
2. Restrict **nprobe** to IVF lists that still contain enough candidates after intersection (or intersect candidate IDs with IVF list contents).
3. Run **distance computation / ANN refinement** only on the surviving candidate set.

The design targets **high-selectivity AND** queries where naive IVF still touches too many vectors.

## 3. Spatial Query Suitability

| Query type | Assessment |
|------------|------------|
| **ST_Contains(polygon, point)** | **CONDITIONALLY SUITABLE.** Polygons are not native “inverted list keys” in IVF² as published; you must **discretize** space (S2/H3 cell IDs, grid tiles) or maintain a **secondary spatial posting structure** (cell → row IDs) and intersect with IVF postings. Exact containment still needs a refinement phase on candidates. |
| **ST_DWithin(point, point, r)** | **CONDITIONALLY SUITABLE.** Same as above: approximate with **disk/circle covering** by cell unions, intersect postings, then **exact distance filter**. Works well when `r` is small (few cells). |
| **ST_Intersects(geom, geom)** | **CONDITIONALLY SUITABLE.** General geometries reduce to **bounding spatial keys** (MBR, cell cover) for the inverted layer; exact intersection is a **posting refinement** step. Worst case resembles spatial-first cascade if coverings are loose. |
| **Lat/lon range predicates** | **SUITABLE (as structured filters).** Axis-aligned ranges map cleanly to **Z-order / Hilbert** bit prefixes, B-tree ranges, or **per-dimension inverted strips**—the same “classic inverted index” slot IVF² uses for non-vector metadata. |

## 4. Evidence

- **Hybrid survey** (`research/01_literature_survey/hybrid_approaches.md`): IVF² **“drastically reduces candidate search space”** for **high-selectivity AND** vs. baseline IVF; uses **memory-efficient bitvectors** for metadata.
- **Taxonomy** (`research/03_algorithmic_design/approach_taxonomy.md`): IVF² is explicitly classified as **index-level dual-index fusion**—aligned with StarRocks patterns that already separate structured filters from vector scans.
- **Complexity (qualitative)**: IVF query cost is typically \(O(\text{nprobe} \cdot \text{list\_size})\) distance touches; IVF² pushes this down by **intersecting** postings first—gains are largest when metadata/spatial keys eliminate most IDs.

## 5. Proposed Spatial Optimizations

1. **S2 cell ID as first-class inverted key**: Store `s2_cell_id` (fixed level or adaptive) in the same posting intersection pipeline as other attributes; intersect S2 cell postings from query covering with IVF lists.
2. **Two-tier refinement**: Coarse **cell bitmap** → IVF **nprobe** only on overlapping centroids that still have surviving IDs → **exact** `ST_*` on short lists.
3. **Segment-local statistics**: Per-segment cell frequency histograms to choose **nprobe** vs. **bitmap-first** order (see selectivity table in `research/01_literature_survey/filtered_ann.md`).
4. **Compatibility with columnar deletes**: Represent surviving IDs in Roaring/segment bitsets to match StarRocks’ vector reader delete filters.

## 6. Verdict

**CONDITIONALLY SUITABLE**

Justification: IVF² is a strong fit for **discretized spatial keys + vector IVF** and for **range predicates** on coordinates. It is **not** a drop-in for arbitrary **WKT polygons** without a **spatial discretization or auxiliary spatial index** layer. With S2 covering + refinement (as already conceptualized in `research/03_algorithmic_design/spatial_partitioned_hnsw.md` and `cascade_pipeline.md`), it becomes a **practical** fusion pattern.

## 7. StarRocks Fit

- **TenANN IVF / IVFPQ** already exists (`research/01_literature_survey/vector_indexes.md`); IVF²-style fusion maps to **planner + execution**: bitmap / inverted filters from the storage layer intersect candidate row IDs before distance scans.
- **Inverted index and bitmap infrastructure** in the OLAP engine aligns with the **classic inverted index** side of IVF².
- **Segment boundaries**: Build fusion **per segment** (or per tablet) with local centroids; global IVF² would require coordinated training—usually unnecessary if queries hit single segments.
- **Gap**: A **native polygon→postings** path is still needed for best `ST_Contains` performance; until then, **cell coverings + exact verify** is the realistic integration.
